怎么用这份安排

  1. 功能以 需求分析（TypeScript） 为准。这里只规定顺序。做的时候对照需求里的编号，例如 F5、F8。
  2. 一天做不完就停在当天，不要把后面的跳过去。跨链对话依赖前面的只读接口。
  3. 第 7 周之前不接 MetaMask，不调用 createTx。前六周把桥当成只读 API。
  4. 每天下班在 wan-agent/NOTES.md 写 5 行：做了什么、哪条命令成功了、卡在哪、明天第一件事。
  5. 会 TypeScript 的话，第 1 周可以压成 2 天。不会就按天走，不要同时学 React。

卡住时

现象先做
不知道 LangGraph 的节点是什么停在第 16 天。只做一个 async 节点、一条边，用 console.log 代替模型。跑通再加第二个节点。
模型不调用工具，自己编费用费用不要让模型算。TypeScript 算好中文句子，模型只能朗读这句或追问缺失项。
USDC 找到很多条这是正确行为。把地址列出来让人选。不要在提示词里写「选最常见的」。
maxQuota 看起来像天文数字回到第 8 天。那是最小单位，用 formatUnits。如果后几位和手工算的不一致，说明用了 number，回到第 3 天的 json-bigint。
res.json() 之后额度对不上删掉 res.json()。先 text()，再 JSONBig({ storeAsString: true })。
钱包网络号和文档表格对不上用 createTx 返回的 data.chainId。文档表格里的 2147… 不是 MetaMask 的网络号。发给 wallet_switchEthereumChain 时把这个十进制数写成 0x 十六进制。
sqlite 的包编译失败把报错记到 NOTES.md。先用 MemorySaver 把第 4 周做完。验收前再装一次。进程不能关，否则会话会丢。
bge-m3 下载太慢或内存不够pipeline 加 dtype: "q8"。还不行就改 Xenova/multilingual-e5-base，并加上 passage / query 前缀。名字只改 config 一处。
createTx 返回 success false把响应正文记到日志。常见原因是币对方向的代币地址拿反、金额格式、或链不在桥上。不要改用手工拼交易 data。
想顺便做比特币、XFlows 或 React写进「以后再做」，回到当天的勾选。范围变化要先改需求分析再改代码。
测试网没有这条币对第 7 周用限额内的主网最小金额。前 6 周不需要真币。
做完时你应该能向别人演示 打开 http://127.0.0.1:5173，问一个文档问题并点开来源；发起一笔 8 条链之内的小额跨链，在确认卡核对地址后用自己的钱包签名；粘贴哈希看到中文状态。演示里没有出现助记词输入框。
